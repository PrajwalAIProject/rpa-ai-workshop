# Course alignment — BCG701

This workshop is designed to **extend**, not repeat, *BCG701 — Robotic Process Automation
Design and Development (UiPath)*. BCG701 already takes students through UiPath **StudioX**
in real depth (common activities, UI automation, Mail/Word/Excel, File and Presentation
automation). So this session never re-explains "what is RPA" — it starts where the
syllabus stops and climbs into professional Studio, cloud Orchestrator, and an agentic AI
layer.

This page is for showing the faculty (Prof. Yogesh N) that the session is **additive**:
every Course Outcome the course already defines is carried forward and built on, not
re-taught.

## How this workshop extends each Course Outcome

| CO | BCG701 Course Outcome | How this workshop extends it |
| -- | --------------------- | ---------------------------- |
| **CO-1** | Common RPA concepts in StudioX | Extended into *why* ROI and orchestration decisions get made the way they do in production — the automation maturity curve beyond the citizen-developer canvas. |
| **CO-2** | UI automation in StudioX | Extended into professional **UiPath Studio** plus exception handling at scale — variables, arguments, reusable workflows, and retry/escalate rules in Orchestrator. |
| **CO-3** | Mail & Word automation | Referenced in the hiring-metrics discussion as a known capability, then built on rather than re-taught. |
| **CO-4** | Excel automation | Reused directly: Project 3 basic rebuilds a BCG701 Excel exercise in Studio Pro. |
| **CO-5** | File & Presentation automation | Reused inside Project 3's reporting/workflow steps. |

## In short

BCG701 gives students the **hands** (RPA that executes defined steps). This workshop adds
the **judgment** (an AI/agentic layer that decides what to do when a process deviates) and
the surrounding professional practice — Studio, Orchestrator, Python, APIs, and cloud
scheduling. Confirming this CO mapping with Prof. Yogesh N up front is what turns a guest
session into something the department can formally credit.
